# Специфікація процесу: UC-5 «Оформити замовлення» та UC-6 «Обробити підтвердження оплати»

## 1. Намір та Межі (Scope)
- **Намір**: Описати бізнес-процес бронювання мерчу My Little Pony Online, перевірки складських залишків, обробки платежу через PaymentGateway, зняття залишків та фіналізації замовлення у вигляді UML Activity-діаграми з доріжками відповідальності (Swimlanes).
- **Вхідні умови**: Покупець перебуває в кошику з обраними позиціями `cartItems` та ініціює оформлення (`submitCheckout`).
- **Вихідні умови**: Замовлення переведено в статус `paid`, залишки товарів списано (`commitStockDeduction`), згенеровано чек і відправлено сповіщення АБО замовлення скасовано (`cancelled`), тимчасовий резерв `Hold` у Storage знято.
- **Out of Scope**: Реєстрація нового користувача (припускається авторизований сеанс) та повернення коштів (Refund UC).

## 2. Доріжки відповідальності (Swimlanes) та Компоненти
1. **Client / UI (Покупець та Інтерфейс)**: Введення даних, підтвердження замовлення (`submitCheckout`), пре-валідація статусу `User.status == active`, редирект на платіжний шлюз, обробка відповідей UI та запит на повторну оплату.
2. **System (Order & Stock Service - Backend)**: Перевірка повторного списання (`Pending`), верифікація та виділення складових резервів (`Hold`), створення запису `Order` (`status='created'`), виклик `PaymentService`, а також виконання паралельних дій (`Fork / Join`) при успішній оплаті (`commitStockDeduction` + сповіщення).
3. **Payment Gateway (Платіжний шлюз)**: Прийом платіжної сесії, взаємодія з банком та відправка асинхронного Webhook (`PAID` / `FAILED` / `TTL Timeout`).

## 3. Покриття сценаріїв UC-5 (Завдання 2 та 3)
- **UC5-S1 (Основний успішний)**: `Client` підтверджує -> `System` перевіряє `stock_quantity` та створює `insertOrder(status='created')` -> Редирект на `Payment Gateway`.
- **UC5-S2 (Успішна оплата / UC-6)**: `Payment Gateway` відправляв Webhook `PAID` -> `System` через `Fork` запускає паралельно `commitStockDeduction` та сповіщення -> `Join` переводить у `status='paid'`.
- **UC5-S3 (Помилка оплати / UC-6)**: Webhook `FAILED` -> `System` міняє `status='cancelled'` -> `Release` резерву -> `Client` отримує повідомлення про помилку.
- **UC5-S4 (Блокування повторного списання)**: `System` виявляє замовлення у статусі `'created'` -> Заборона дублювання запиту (`Block`).
- **UC5-S5 (Повторна оплата після помилки)**: `Client` обирає повтор оплати після помилки -> `Retry` перенаправляє потік назад до створення замовлення/ініціалізації оплати в `System`.
- **UC5-S6 (Недостатній залишок / Неавторизований)**: Переривання процесу при `stock_quantity < quantity` або `User.status != 'active'`.
