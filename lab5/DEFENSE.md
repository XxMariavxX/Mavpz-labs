# DEFENSE — Завдання 5: Архітектура (Component)

## 1. Намір і критерії

* **Намір**: описати архітектуру платформи (UI, API, сервіси, Data Access, БД) та зовнішні інтеграції однією Component-діаграмою з чіткою межею системи. Узгоджено з ERD (lab1), UC/EARS (lab2), Sequence (lab3) і процесом (lab4)

* **Критерії**:
  * Одна діаграма; компоненти та зовнішні інтеграції позначені
  * Присутні provided/required-інтерфейси та залежності
  * Чітка межа системи (система і зовнішні інтеграції)
  * Повністю покриті модулі з `spec.md`
  * Діаграма рендериться засобами Mermaid
  * Рендериться в PLantText без помилок

* **Out of Scope (непокриті умови)**:
  * Інфраструктура (k8s, CI/CD), моніторинг, кешування, CDN.
  * C4-нотація Mermaid: використано `flowchart LR` для сумісності з GitHub.
  * OAuth Provider додано як зовнішня інтеграція (OA) понад попередні моделі.
  * Database винесено за межу системи (за рекомендацією викладача).
  * NotificationService додано для узгодження з email/relay у lab4.

## 2. Топ-3 розбіжності (перша версія ↔ spec) і виправлення

1. **Монолітний backend**:
   * **Проблема**: сервіси замовлення, залишку та оплати були об'єднані в один компонент, що приховувало залежності.
   * **Виправлення**: розділено на `OrderService`, `InventoryService`, `PaymentService` з явними інтерфейсами.
   *Коміт*: `e690e51` — `feat: add architecture documentation for component design and specifications`

2. **Розкиданий доступ до БД**:
   * **Проблема**: доступ до БД був у кожному сервісі окремо, без єдиної межі.
   * **Виправлення**: введено шар `Data Access` (Repository) як єдиний provided-інтерфейс до БД.
   *Коміт*: `e690e51` — `feat: add architecture documentation for component design and specifications`

3. **Розмита межа системи**:
   * **Проблема**: зовнішні інтеграції не були позначені як зовнішні, що розмивало межу.
   * **Виправлення**: `PaymentGateway`, `Email/SMS Provider`, `OAuth Provider` винесено за межу як зовнішні інтеграції.
   *Коміт*: `69a14a5` — `fix: clarify database description and external integrations in architecture specification`; остаточно межу та розміщення `Database` уточнено в `9891114`.

## 3. Ключове рішення

Вирішено створити **одну Component-діаграму** з чіткою межею системи та зовнішніми інтеграціями, замість окремих схем на кожен модуль:
* Добре стикується з ERD, UC, Sequence і процесом.
* Єдиний шар Data Access спрощує зміну БД.
* Зовнішні інтеграції ізольовані за межею системи.
* Для гарантованого рендеру на GitHub використано `flowchart LR` з `subgraph` замість `C4Component`.
* Детальніше описано в `adr/adr-0001-component-architecture.md`.
